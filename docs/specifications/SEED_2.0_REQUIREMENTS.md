# SEED 2.0 programme requirements

The supported execution environments are ChatGPT, ChatGPT Work and OpenAI
Codex. Use open Agent Skills metadata and determined Python computation.
Retain the upstream MIT licence and copyright. Production venture data,
credentials and private IP belong outside the repository. Development and CI
use synthetic fixtures, a reviewed development branch and recoverable
checkpoints.

## Functional scope

| Phase | Required work |
| --- | --- |
| P2 | Private SQLite workspaces, versioned evidence and assumption graph, migrations, recovery and explicit record exchange. |
| P3 | Investor and firm evidence, configurable fit separate from confidence, introduction paths, persistent fundraising CRM, outreach suppression and draft-only preparation with explicit action approval. |
| P4 | Reconciled 36/60-month scenarios for software, marketplace, physical products, hardware, manufacturing, biotech, medtech, licensing, services and hybrid. Working capital, cash, capex, capacity and yields, milestones, capital structures and deterministic dilution. |
| P5 | Sourced competitor and market analysis, patent discovery with status caveats, plus grants and accelerator discovery and qualification. Surface freshness, eligibility, economics and missing evidence. |
| P6 | Evidence-backed plan, deck and updates. Technical and commercial readiness, due diligence disclosure levels, investment committee simulation and independent cross-document verification. |
| P7 | Synthetic workflows for SaaS, marketplace, advanced manufacturing, hardware, biotech, medtech and hybrid hardware/AI. Execute regressions, review release risks and verify all 20 skills on all supported hosts. |
| P8 | Reproducible packages and installers, setup, developer and security guides, migration, recovery, synthetic workspaces, operational results and release acceptance. |

Use approved or explicitly configured tools for current primary-source evidence.
Record unknowns and maintain an approval gate before all external writes.
Keep financial outputs deterministic and provenance traceable. Connector
availability, model permissions and search access differ by host. No
filesystem synchronisation is presumed.

The [traceability matrix](../REQUIREMENTS.md) records the implementation,
regressions and acceptance evidence. The [development status](../DEVELOPMENT_STATUS.md)
records the latest checkpoints.
